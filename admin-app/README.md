# Matjar Admin App

تطبيق الأدمن (Mobile-first, React Native + Expo + TypeScript) لإدارة الطلبات والنشر على مواقع التواصل.

## التشغيل محلياً

يحتاج هذا المشروع اتصال إنترنت لتثبيت الحزم (لم يُشغَّل أو يُختبر داخل بيئة بناء هذا المستند نفسها لعدم توفر شبكة هناك):

```bash
cd admin-app
npm install
cp .env.example .env   # ثم عدّل القيم بما يطابق بيئتك
npm start
```

ثم امسح رمز QR بتطبيق Expo Go على هاتفك، أو شغّل `npm run android` / `npm run ios` مع محاكي مثبّت.

لتشغيل الاختبارات: `npm test`.

## ما تم بناؤه في هذه الدفعة

- هيكل مشروع Expo + TypeScript كامل وقابل للتشغيل.
- طبقة API (`src/api`) مطابقة لمخططات `api/openapi.yaml`.
- **شاشة قائمة الطلبات**: فلترة حسب الحالة (بانتظار المراجعة كافتراضي)، سحب للتحديث.
- **شاشة تفاصيل الطلب**: كل البيانات المطلوبة (العميل، المنتجات، إثبات التحويل معروضاً كصورة أو رابط PDF، حالة الطلب)، وأزرار القرار الثلاثة (قبول مع رقم تتبع إلزامي / رفض / نفاد كمية) مع تأكيد قبل التنفيذ.
- قرارات الأدمن تمر عبر n8n (`06 - Order Status Updates`) وليس مباشرة للـ Backend، لأن n8n هو من يرسل النتيجة للعميل عبر WhatsApp.
- **شاشة "النشر"** (تبويب ثانٍ): رفع صورة/فيديو من الجهاز مباشرة (presigned upload)، بحث واختيار منتج حقيقي، توليد وصف بالـ AI قابل للتعديل وإعادة التوليد، اختيار جميع المنصات أو منصة محددة، ونشر فوري أو جدولة تاريخ/وقت.
- بنية تنقل بتبويبين: **الطلبات** و**النشر** (`@react-navigation/bottom-tabs`).
- **تسجيل الدخول**: شاشة كاملة تستدعي `POST /auth/login` (أضفتها للتو إلى `api/openapi.yaml` — كانت غائبة رغم أن bearerAuth كان مذكوراً كمخطط أمان بلا نقطة نهاية فعلية تُصدره). الجلسة (توكن + بيانات الأدمن) تُخزَّن بأمان عبر `expo-secure-store` (وليس AsyncStorage العادي، لأنه توكن مصادقة)، وتُستعاد تلقائياً عند إعادة فتح التطبيق دون طلب دخول جديد. زر "خروج" في رأس شاشة الطلبات.
- **شاشة المحادثات المُصعَّدة للبشر** (تبويب ثالث) — القسم 9 من المواصفات وصفها بأنها "متطلب أساسي": قائمة المحادثات التي تحتاج تدخلاً بشرياً، شاشة محادثة بفقاعات رسائل (تمييز العميل عن البوت/الأدمن)، إرسال رد يدوي فعلي عبر WhatsApp (يمرّ بـ n8n Workflow جديد `11 - Admin Conversation Reply`)، وزر "إنهاء" لإغلاق التصعيد.
- **شاشة قائمة المنشورات** (Drafts/Scheduled/Published/Failed) مع فلترة، وتحويل تبويب "النشر" إلى Stack بشاشتين (قائمة + إنشاء عبر زر "+ جديد").
- **إشعارات Push فعلية**: تسجيل تلقائي لتوكن Expo Push بعد الدخول (أو استعادة الجلسة)، عبر `POST /admin/devices` الجديدة. الـ Backend يرسل عبر خدمة Expo Push نفسها (exp.host) بدل التعامل المباشر مع FCM/APNs — أبسط بكثير لتطبيق مبني بـ Expo أصلاً.
- **اختبارات أولية** (Jest + jest-expo + Testing Library): تغطي `toApiErrorInfo` (4 حالات) وشاشة تسجيل الدخول (عرض، تحقق من حقول فارغة، استدعاء صحيح). نقطة انطلاق فعلية وليست تغطية شاملة.
- **بناء APK تلقائي عبر GitHub Actions** — راجع القسم أدناه.

## ما لم يُبنَ بعد (تحتاج دفعة لاحقة)

- توسيع تغطية الاختبارات لبقية الشاشات وطبقة الـ API.
- شاشة إعدادات عامة (تغيير كلمة المرور، معلومات الحساب).
- دعم أكثر من أدمن بصلاحيات مختلفة (حالياً كل حساب يرى كل شيء).
- **إشعارات Push فعلية** داخل التطبيق (استقبال ما يرسله `/admin/notifications`) — تحتاج تسجيل جهاز عبر Expo Notifications أو FCM/APNs مباشرة.
- اختبارات آلية (لا يوجد أي اختبار حالياً).

## بناء APK تلقائياً عبر GitHub Actions (بدل Expo Go)

يوجد `.github/workflows/eas-build-android.yml` في جذر المستودع — يبني APK فعلياً على خوادم Expo السحابية (EAS Build) عند أي push يغيّر شيئاً داخل `admin-app/`، ويمكن تشغيله يدوياً أيضاً من تبويب **Actions → Build Android APK (EAS) → Run workflow**.

**إعداد لمرة واحدة قبل أول تشغيل:**

1. أنشئ حساب Expo مجاني إن لم يكن لديك: https://expo.dev/signup
2. ولّد توكن وصول: `npx eas-cli login` ثم `npx eas-cli whoami` للتأكد، أو من صفحة إعدادات حسابك على expo.dev → Access Tokens.
3. أضف التوكن كـ secret في مستودع GitHub: **Settings → Secrets and variables → Actions → New repository secret** باسم `EXPO_TOKEN`.
4. **مهم**: شغّل أول بناء **محلياً وبشكل تفاعلي مرة واحدة** قبل الاعتماد على الأتمتة:
   ```bash
   cd admin-app
   npm install
   npx eas-cli login
   npx eas-cli build -p android --profile preview
   ```
   هذا يولّد بيانات توقيع Android (keystore) ويخزّنها على حساب Expo تلقائياً. بدون هذه الخطوة مرة واحدة، أول تشغيل تلقائي عبر GitHub Actions (وهو `--non-interactive` ولا يمكنه أن يسأل أي سؤال) سيفشل لعدم وجود بيانات توقيع.

بعد ذلك، كل push لاحق يبني APK تلقائياً — تابع التقدم من تبويب **Actions**، ورابط تنزيل الـ APK يظهر في نهاية سجل الخطوة الأخيرة (وأيضاً على expo.dev/accounts/[حسابك]/projects).


```
admin-app/
├── App.tsx                      نقطة الدخول
├── src/
│   ├── api/                     عملاء الاتصال بالـ Backend وn8n
│   ├── navigation/               إعداد التنقل بين الشاشات
│   ├── screens/                   الشاشات الفعلية
│   ├── theme/                     الألوان والتنسيقات الموحّدة
│   └── types/                     أنواع TypeScript مطابقة للـ OpenAPI
```
